# Grekam OS — Role-Specific Operating Checklists
### Internal Reference | Updated August 2026

---

> Print this. Pin it to your screen. Follow it every day.
> Your performance review starts here.

---

# CHECKLIST 1 — SALESPERSON

## Daily Morning (Before First Call)

- [ ] Open Grekam OS — this is the first thing you open, not WhatsApp
- [ ] Check **Follow-ups due today** — who did you promise to call?
- [ ] Check **Overdue tasks** — is anything past its deadline?
- [ ] Review your **active pipeline** — which deals need movement today?
- [ ] Identify your **top 3 priorities** for the day
- [ ] Create tasks for each priority before you start working

---

## During the Day (After Every Interaction)

- [ ] Log every call within 10 minutes of the call ending
  - Outcome: What happened?
  - Next step: What comes next?
  - Follow-up date: When exactly?
- [ ] Update the lead status if it changed
- [ ] Create a new follow-up task immediately
- [ ] If a demo is done — update stage to "Demo Completed" and log full notes
- [ ] If a proposal is sent — attach it to the deal record and update stage
- [ ] If a deal is closed — update stage to "Closed Won" and create onboarding task

---

## End of Day (Before Closing Grekam OS)

- [ ] Every lead you spoke to today has an updated note
- [ ] Every active lead has a next follow-up date (no lead without a date)
- [ ] Every task due today is either completed or rescheduled with a note
- [ ] No deal is sitting in the same stage for more than 3 days without a note
- [ ] Pipeline value and stages are accurate — not optimistic, not outdated
- [ ] Fill in your daily report:

```
New leads created:
Calls made:
Leads qualified:
Demos conducted:
Proposals sent:
Deals closed:
Revenue collected:
Key issues:
Tomorrow's top 3:
```

---

## Weekly (Every Friday Before EOD)

- [ ] Review full pipeline — identify stale opportunities
- [ ] For every deal in "Proposal Sent" for more than 5 days — create a follow-up
- [ ] For every deal in "Negotiation" for more than 7 days — flag for manager review
- [ ] Ensure all leads marked "Closed Lost" have a reason recorded
- [ ] Review this week's activity numbers honestly against target
- [ ] Submit weekly report to manager

---

## Weekly Self-Check Questions

Answer these from Grekam OS data alone:

1. How many new leads did I create this week?
2. How many did I qualify?
3. How many demos did I do?
4. How many proposals did I send?
5. What is my current pipeline value?
6. What am I expecting to close next week?
7. Which deal is most at risk and why?

- [ ] Check **all pipelines** — any lead with no activity in 3+ days?
- [ ] Check **project updates** — any project not updated in 48 hours?
- [ ] Review **payment pending deals** — what is expected to collect today?

- [ ] Log any client conversations you personally conducted

# CHECKLIST 3 — DEVELOPER / DESIGNER

## Daily Morning

- [ ] Open Grekam OS before opening your code editor
- [ ] Check **tasks assigned to me** — what is due today?
- [ ] Check **tasks due this week** — what needs to be started now to meet the deadline?
- [ ] Flag any task that has unclear requirements — **before** you begin working on it
- [ ] If you have a blocker from yesterday — update the task and notify the project manager

---

## During the Day

- [ ] Update task status as you move through work:
  - Begin work → mark In Progress
  - Hit a blocker → mark Blocked + explain in notes
  - Finish work → mark Completed immediately
- [ ] Every blocker note must include:
  - What the blocker is
  - Who or what is needed to unblock it
  - When you raised it
- [ ] Do not begin work that is not recorded as a task
- [ ] If scope changes during development — flag it immediately, do not silently absorb it

---

## End of Day

- [ ] Every task is in the correct status
- [ ] Every project you are working on has a progress update note
- [ ] No task is "In Progress" for more than the estimated time without a note explaining
- [ ] If you will miss a deadline: the project manager knows **today**, not on the deadline day

---

## Weekly

- [ ] Review all tasks assigned to you for the coming week
- [ ] Identify tasks with unclear specifications and clarify **before** the due date
- [ ] For every project you are contributing to — update the progress % honestly
- [ ] Ensure all completed tasks from last week are marked closed with completion notes

---

## Developer/Designer Weekly Self-Check

1. Are all my tasks accurately reflecting real status?
2. Is there anything I said would be done that isn't — and does the right person know?
3. Is there any task I'm about to miss that I haven't communicated?
4. If my manager checked my task list right now, would it match reality?

# CHECKLIST 4 — SUPPORT / OPERATIONS

## Daily Morning

- [ ] Check all **open customer issues** from yesterday — any still unresolved?
- [ ] Check for **new customer escalations** logged overnight
- [ ] Check payment status — any customer with an overdue invoice?
- [ ] Identify today's onboarding tasks — any new customers starting today?

---

## During the Day

- [ ] Every customer issue is logged as a task linked to their customer record
- [ ] When a customer issue is resolved:
  - Mark task complete
  - Add a resolution note to the customer record
  - If it was a recurring issue — flag it for process improvement
- [ ] Any issue that requires management input → escalate with a recommendation, not just the problem
- [ ] Customer onboarding sessions → log in the customer record with session notes

---

## End of Day

- [ ] No open customer issue has been sitting without an update for more than 24 hours
- [ ] All resolved issues have documented resolutions in the customer record
- [ ] Any pending payment follow-ups are logged with next contact date

---

## Weekly

- [ ] Review all customers who have been onboarded in the last 30 days
  - Are they actively using the product?
  - Have they raised any issues?
  - Is there an upsell opportunity?
- [ ] Review any recurring support issues — should any become a FAQ or training resource?

# UNIVERSAL RULES — All Roles

These apply to every person in the company regardless of role:

---

### The 10-Minute Rule
Log every interaction within 10 minutes of it happening. After 10 minutes, context begins to fade.

### The Specific Date Rule
Every task, follow-up, and next action must have a specific date and time. "Soon," "this week," and "later" are not dates.

### The Blocker Rule
Raise blockers when they happen. Not on the deadline day.

### The Handover Rule
At any point, your manager should be able to handle your work from Grekam OS alone, without calling you.

### The Completed Rule
Mark tasks complete the moment they are done. Not at end of day. Not in batches.

### The Reason Rule
When something is late, rescheduled, cancelled, or lost — document the reason. Data without context is noise.
