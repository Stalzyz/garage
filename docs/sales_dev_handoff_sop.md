# Grekam — Sales-to-Development Handoff SOP
### Version 1.0 | Internal Operations Document | August 2026

---

> The moment payment is received,
> sales responsibility shifts to delivery responsibility.
> The handoff is where most projects fail — not in development.
>
> A developer who has to ask "what did sales promise?"
> is already behind schedule.

---

# THE CORE RULE

**The development team should never have to contact the salesperson to understand the project.**

Everything that was discussed, agreed, promised, and expected must be in writing before the first development task is created.

If it was not written down, it does not transfer.
If it does not transfer, it becomes a dispute.

---

# WHO IS RESPONSIBLE FOR WHAT

| Responsibility | Owner |
|---|---|
| Completing the handoff form | Salesperson |
| Reviewing the handoff form for completeness | Business Development Manager |
| Approving scope before development begins | Business Development Manager |
| Conducting the kick-off call with the client | Project Manager / BDM |
| Managing the project post-handoff | Project Manager |
| Escalating scope changes to sales | Project Manager |
| Updating the customer record | Both — jointly |

---

# WHEN THE HANDOFF HAPPENS

The handoff form must be completed:
- **Within 24 hours of payment confirmation**
- **Before any development task is created**
- **Before the first development call is scheduled**

Development does not begin until the handoff is approved by the BDM.

# THE KICK-OFF CALL

After the handoff form is approved, the Project Manager conducts a kick-off call with the customer.

**Purpose:** Align the customer, project manager, and delivery team on scope, timeline, and communication process before work begins.

**This call should NOT be skipped, even for small projects.**

---

## Kick-Off Call Agenda

1. **Introductions** — Who is managing this project going forward?
2. **Scope confirmation** — Review the agreed deliverables together
3. **Timeline** — Confirm the delivery date and key milestones
4. **Revision process** — Explain how feedback rounds work
5. **Content deadlines** — Confirm what the client needs to provide and when
6. **Communication** — How often will we update them? What channel?
7. **Point of contact** — One person on each side for all communication
8. **Out-of-scope** — Explicitly confirm what is NOT included (avoid future disputes)
9. **Next step** — What happens after this call?

# SCOPE CHANGE PROTOCOL

After the kick-off call, any change to the agreed scope must follow this process:

1. **Client requests a change** — via any channel
2. **Project Manager receives the request** — logs it in Grekam OS
3. **PM evaluates impact** — timeline impact, cost impact
4. **BDM reviews** — is this within acceptable scope? Does it require additional cost?
5. **Client is informed** — of any timeline or cost impact, in writing
6. **Written approval required** — before implementing any change
7. **If additional cost is agreed** — sales creates an addendum or new proposal

### The Rule on Scope Changes

> No developer begins work on a changed or additional scope item without written client approval.

If a client says "just add this one small thing," the answer is:
> "I can check the impact on scope and timeline and come back to you. If it's minor, we can include it. If it changes scope, I'll need to confirm with you in writing before we begin."

# COMMON HANDOFF FAILURES AND HOW TO PREVENT THEM

| Failure | Cause | Prevention |
|---|---|---|
| Developer doesn't know the delivery date | Salesperson didn't document it | Mandatory field in handoff form — cannot be blank |
| Client expects a feature not in scope | Salesperson said "we can probably do that" | Anything said verbally must be documented in Section D or Section E |
| Design revisions spiral beyond agreed rounds | Revision limit not communicated | Document and communicate revision rounds in kick-off call |
| Content not received — project stalls | No content deadline agreed | Set content deadline in handoff form and confirm in kick-off |
| Client contacts developer directly — bypasses PM | No single contact defined | Define single point of contact in kick-off call |
| Discount given in sales affects delivery budget | Margin not communicated to PM | Section G — internal margin must be completed |
| Client says "I was told this was included" | Scope not confirmed in writing | Written kick-off confirmation and scope sign-off resolves this |
